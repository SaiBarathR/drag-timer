# Drag Timer 1.5.0 release checklist

## Release scope

| Item | Result | Evidence |
| --- | --- | --- |
| Drag feel unchanged from 1.4 | Pass | Owner asked for the default drag and release to be kept as they were and confirmed the opening snap flash at 1 minute is intended. `DragFeelLockTests` (PR #26) records the 1.4.1 behaviour and passed unchanged through PRs #27 to #36 |
| Timers ring while the name prompt is open | Pass | PR #36: a test runs the real modal prompt with the real scheduler and a 1-second timer; it fails on the previous code and passes now |
| Dragged timer starts at release; prompt renames or discards | Pass | PRs #25 and #36 with unit and gesture-controller tests |
| Typed lengths and status-item menu | Pass | PR #33: exercised in the running debug build through the Accessibility API with real clicks and keystrokes |
| Pre-release review | Pass | Everything since `v1.4.1` reviewed by Opus 5.5 (xhigh), gpt-6.1 sol and Grok 4.7; 17 findings, 15 fixed or mitigated and 2 skipped with reasons in PR #36 |
| Version classification | Pass | New user-visible features (typed lengths, Add time, Mark done, status-item menu), so the release advances from 1.4.1 to 1.5.0 |
| Release notes | Pass | `docs/releases/v1.5.0.md` |

## Publication gate

The annotated `v1.5.0` tag may be pushed only after this checklist, release notes, version bump, and documentation are committed on `main`. The tag-triggered GitHub Actions workflow must independently repeat the build, tests, universal packaging, signature verification, clean extraction, and checksum gates before it publishes the GitHub release.

# Drag Timer 1.6.1 release checklist

## Release scope

| Item | Result | Evidence |
| --- | --- | --- |
| Drag feel unchanged from 1.6.0 | Pass | `DragFeelLockTests` passed unchanged. PR #46 does not touch the ruler, detents, snapping or the release path. Ordinary, cancelled and Escaped drags were made on builds of the branch with real pointer events |
| Popover follows its content | Pass | PR #46. Both reported layouts reproduced on the published 1.6.0 and gone on the candidate: a finished timer with the Undo offer (Quick start heading inside, footer inside, 555 points), and a preset started after a timer finished in the open popover (list 58 points, countdown showing) |
| Popover stops at the screen's height | Pass with a limit | PR #46. Covered by `testThePopoverStopsGrowingAtTheHeightOfItsScreen`. The test Mac's screen is too tall to reach the limit, so the layout was looked at in a throwaway build with the limit forced to 430 points; that build was not committed |
| Popover stays where it opened | Pass | PR #46. Opened with nothing running, then five timers and an expiry, the menu-bar item going from 32 to 62 to 71 points: the published 1.6.0 moved the popover from x = 1132 to 1129 and then 1099; the candidate held its place throughout. Pushed off its spot by a neighbouring menu-bar item quitting, on a debug build of the same source, it moved 42 of the item's 48 points at once and did not move again |
| Timer details stays put | Pass | PR #46. With details open on one of four timers and another finishing behind it, popover, sheet and Save changes kept their frames on the candidate; the popover went from 556 to 578 points when the sheet was closed |
| Name prompt follows its timer | Pass | PR #46. "Finished at 4:09 PM" after the timer rang, with the saved name on the card, in the menu-bar label and in History; "Paused · 0:57 left" and back to "Running"; closed 0.8 s after its timer was stopped, with a typed name kept on the History entry |
| Restore Snappy drag defaults | Pass | PR #46. `testRestoringDragDefaultsPutsTheWholeFeelPaneBackToANewInstall`; confirmed hands-on by gpt-6.1 sol on a build of the branch (maximum 5 to 4 hr, snapping, haptics and double tick back on, snap range 40 to 24 s), with the Preset menu still leaving those alone |
| Volume readout | Pass | PR #46. `testAVolumeJustAboveZeroDoesNotReadAsZero`; the candidate shows 1% at a volume of 0.0042 |
| Hands-on review | Pass with limits | gpt-6.1 sol used the app five times on 2026-10-08: the published 1.6.0 for 34 minutes (four findings, all valid and fixed), then builds of the branch (second pass: the four fixed, one new finding; third: that one fixed, a sideways shift noted; fourth: the shift fixed, one finding about the name prompt). The fifth, on the build before the last commit, was cut off by Codex's usage limit before it wrote a report; its progress notes record the name prompt and the sideways check as passing, with no defect noted. How the passes were done, and their limits, are in PR #46 and under "Not verified" below |
| Code review | Pass | Grok 4.7 (high) reviewed PR #46 five times: eight findings over the first four passes, six fixed and two skipped with reasons on the pull request, and a fifth pass that found nothing |
| Version classification | Pass | Bug fixes only, so the release advances from 1.6.0 to 1.6.1 |
| Release notes | Pass | `docs/releases/v1.6.1.md` |

## Publication gate

The annotated `v1.6.1` tag may be pushed only after this checklist, release notes, version bump, and documentation are committed on `main`. The tag-triggered GitHub Actions workflow must independently repeat the build, tests, universal packaging, signature verification, clean extraction, and checksum gates before it publishes the GitHub release.

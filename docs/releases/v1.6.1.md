# Drag Timer 1.6.1

## Highlights

Drag Timer 1.6.1 fixes the timer popover losing track of its contents while it was open. In 1.6.0 an open popover kept the size it had been opened with, so a timer finishing or starting in it, or the new Undo offer, could squeeze the timer list to nothing or push the presets and the footer out of view. The popover now resizes to what is in it and stays where it is while you use it. There are no new features and no changes to the drag.

## The popover

- **It follows its content.** A running timer and its controls could vanish from an open popover while the footer still said "1 running". With a named preset or a routine set up, a finished timer together with the Undo offer could push the Quick start row and the History, Settings and menu buttons out of view. Closing and reopening the popover put it right. It now grows and shrinks with its content for as long as it is open.
- **It stops at the height of the screen.** On a small screen the popover no longer grows past what fits below the menu bar; the timer list scrolls instead.
- **It no longer jumps sideways.** The menu-bar item gets wider when a countdown or a finished timer's count-up appears in it. An open popover used to follow it late, jumping about 30 points at some later moment and taking Timer details with it. This was in 1.6.0 and earlier. An open popover now stays where it opened, and moves only if other menu-bar items push the icon right off that spot.
- **Timer details stays put** when another timer finishes behind it. The popover takes its new size when the sheet closes.

## The name prompt

The prompt shown after a drag stays open over a timer that is already running.

- Left open until the timer rang, it went on reading "Running · rings at 4:01 PM, 0:00 left". It now reads "Finished at 4:01 PM". A name saved then still reaches the finished card and History, as before.
- It reads "Paused" with the time left for a timer that has been paused.
- When its timer is stopped or marked done some other way, the prompt closes by itself instead of counting down a timer that no longer exists. A name already typed is kept: it goes on the History entry, and on the timer if Undo brings it back.

## Preferences

- **Restore Snappy drag defaults** now puts every control of the Feel pane back to how a new install has it. It used to leave snapping, haptics, the double tick and the maximum drag duration as they were. Choosing a preset from the Preset menu still changes only the release behaviour.
- The **Volume** readout no longer shows "0%" for a volume above zero. It shows at least 1% and rounds instead of truncating.

## Upgrade behavior

- No stored format changed. Timers, presets, routines, history, expiry cards and settings from 1.6.0 load as they are, and going back to 1.6.0 needs nothing.
- The drag ruler, detents, snap points and release behaviour are unchanged.

## Compatibility

- Requires macOS 14 or newer.
- Apple Silicon runtime is verified.
- The universal app contains native `arm64` and `x86_64` slices. Physical Intel runtime testing remains unavailable, so Intel support is provisional rather than claimed as verified.

## Installation

1. Download `Drag-Timer-1.6.1-macos-universal.zip` and `SHA256SUMS.txt`.
2. Keep both files in the same directory and run `shasum -a 256 -c SHA256SUMS.txt`.
3. Unzip the archive and replace the existing `Drag Timer.app` in Applications.
4. Control-click the app, choose **Open**, and confirm. You can also use **Open Anyway** in System Settings > Privacy & Security.

Drag Timer is ad-hoc signed rather than Developer ID signed or notarized, so macOS requires this one-time Gatekeeper confirmation.

## Verification

After extraction, verify the universal executable, signature, and version:

```sh
lipo -archs "Drag Timer.app/Contents/MacOS/DragTimer"
codesign --verify --deep --strict --verbose=2 "Drag Timer.app"
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "Drag Timer.app/Contents/Info.plist"
```

The commands should report both `arm64` and `x86_64`, a valid ad-hoc signature, and version `1.6.1`.

# Drag Timer 1.5.0

## Highlights

Drag Timer 1.5.0 keeps the drag exactly as it felt in 1.4 and reworks what happens around it. A dragged timer now starts the moment you release, so naming it never costs you time. Timers can be started by typing a length, finished early, and extended. It also fixes a bug in which no timer could ring while the name prompt was open.

## Starting and naming timers

- A dragged timer starts at release. The name prompt renames the running timer instead of delaying it, so a 5-minute drag is always 5 minutes, however long you take to type.
- In the prompt, Return saves the name, Escape keeps the timer under its default name, and **Discard Timer** removes it. Names can span several lines with Shift-Return.
- **Fixed:** while the name prompt was open, no timer could ring. Timers now ring on time whether or not the prompt is showing. This also affected 1.4.1.
- **Other length…** under Quick start starts a timer from typed text such as `7`, `25m`, `1h 30m` or `1:30` (hours and minutes). The Start button names the length it read.
- On the very first launch the popover opens once, and macOS asks for notification permission when you start your first timer rather than at launch.

## Managing running timers

- **Mark done** finishes a running timer early. It is recorded as completed and never rings.
- **Add N min** in a timer's `…` menu pushes it back by its snooze length. It replaces Snooze on running timers, which used to cut the remaining time down to the snooze length. Snooze on a finished timer is unchanged.
- Rows hold their position while the pointer is over the list, so pausing a timer no longer moves it out from under the pointer.
- Right-click the menu-bar icon for Show Timers, Timer History, Settings and Quit. Quit also moved into a **More** menu in the popover footer.
- The countdown in the popover now reads the same as the menu bar (`4:05`) and both change at the same instant.

## Presets, routines and Preferences

- Preset and routine editors take a typed duration instead of a one-minute stepper, list symbols by name (Coffee, Reading, Laundry) and name colours for the colour shown.
- The Feel pane shows the value of every slider, disables Spring when inertia is off (where it has no effect), and no longer offers a "Custom" preset that could not be selected.
- History shows everything that is kept, 90 days, instead of the last 30.
- Text fields accept the standard Command shortcuts for paste, copy, cut, undo and select all.

## Fixes

- The timer symbol in the menu bar was always black. It now uses the timer's colour, and red when urgent.
- A damaged `timers.json` or `pending-expiries.json` is moved aside and readable timers are kept, instead of every running timer being lost.
- The update check no longer writes settings from a background thread.
- Snap range is limited to 40 seconds. Above that, values next to a snap point could not be selected. A larger saved value is lowered to 40.
- The "up to 12 presets" message clears once a preset is removed.

## Upgrade behavior

- Existing timers, presets, routines, history, expiry cards and settings remain compatible. Stored formats are unchanged.
- The drag ruler, detents, snap points and release behaviour are unchanged from 1.4, and are now pinned by tests.
- The development `--self-test` flag was removed; its checks moved into the test suite.

## Compatibility

- Requires macOS 14 or newer.
- Apple Silicon runtime is verified.
- The universal app contains native `arm64` and `x86_64` slices. Physical Intel runtime testing remains unavailable, so Intel support is provisional rather than claimed as verified.

## Installation

1. Download `Drag-Timer-1.5.0-macos-universal.zip` and `SHA256SUMS.txt`.
2. Keep both files in the same directory and run `shasum -a 256 -c SHA256SUMS.txt`.
3. Unzip the archive and replace the existing `Drag Timer.app` in Applications.
4. Control-click the app, choose **Open**, and confirm. You can also use **Open Anyway** in System Settings > Privacy & Security.

Drag Timer is ad-hoc signed rather than Developer ID signed or notarized, so macOS requires this one-time Gatekeeper confirmation.

## Verification

After extraction, verify the universal executable, signature, and version:

```sh
lipo -archs "Drag Timer.app/Contents/MacOS/DragTimer"
codesign --verify --deep --strict --verbose=2 "Drag Timer.app"
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "Drag Timer.app/Contents/Info.plist"
```

The commands should report both `arm64` and `x86_64`, a valid ad-hoc signature, and version `1.5.0`.
